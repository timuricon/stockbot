## Поток данных — Оценка сигналов

```
Кнопка "📈 Оценка сигналов" / APScheduler 20:00 CET (Пн–Пт)
        │
        ▼
run_evaluation_thread()  [фоновый поток, без таймаута]
  кнопка: прогресс каждые 10 сигналов; расписание: молчит если
  оценивать нечего (notify_noop=False)
        │
        ▼
run_evaluation()
        │
        ▼
_list_snapshots() → analytics_history/*.json без *_evaluated.json
  • возраст < 30 дней → skip, счётчик skipped_fresh (Polygon не вызывается)
  • top_picks=[] → помечается skipped_empty, счётчик empty_snapshots
  • иначе → оценка
        │
        ▼
_evaluate_signal()  (пауза 13с между запросами — free tier 5 req/min)
  → _fetch_closes_after(retries=2) → Polygon daily bars
  → _pnl_at_horizon() → P&L на +5/+10/+20 дней
  → _hit_target() → достигла ли swing target
        │
        ▼
*_evaluated.json (рядом с оригиналом)
        │
        ▼
format_evaluation_report()
  полный отчёт: оценено / свежих пропущено / пустых / дата созревания
  если оценивать нечего → накопленная статистика по всем
  *_evaluated.json (aggregate_evaluated_stats)
```

## Скоринг Unified Scan

| Модуль       | Макс | Жёсткие фильтры                           |
|--------------|------|-------------------------------------------|
| Swing        | 40   | цена > 30W EMA, апсайд ≥25%, R/R ≥1.5    |
| Momentum     | 30   | объём ≥1.3×SMA10, хотя бы 1 паттерн      |
| Early Trend  | 30   | EMA10>EMA30>EMA50, Close>EMA200, vol≥300K |
| Combo x2     | +20  | прошли 2 модуля                           |
| Combo x3     | +40  | прошли все 3                              |
| **Итого макс** | **140** | → нормализация к 100, порог ≥60      |

## Отмена сканов

```
Кнопка «❌ Отменить скан» (unified/superstock/et_only)  или  /stop
        │
        ▼
state.unified.cancel_event / state.unified.et_only_cancel_event /
state.superstock.cancel_event  →  .set()
        │
        ▼
Скан проверяет is_set() в начале каждой итерации цикла
(ДО Polygon-запросов) → лог "[Unified|ET-only|SS] Cancelled at i/total"
        │
        ▼
Паузы между тикерами прерываемые (_interruptible_pause):
cancel_event.wait(13s) вместо time.sleep — отмена срабатывает сразу
        │
        ▼
Частичные результаты доставляются в чат с пометкой
«⏹ Скан прерван вручную — показаны частичные результаты»
running=False восстанавливается в finally.
```

Примечание: после удаления growth-сканера файл `growth_tickers_cache.json`
на сервере можно удалить вручную (код его больше не читает и не пишет).

## Диагностика

После каждого unified скана в bot.log:

```
[Swing диагностика] Причины отсева:
  below_ema  : XXX (XX%)   ← главный индикатор состояния рынка
  no_trend   : XXX (XX%)
  no_up_weeks: XXX (XX%)
  zone_d     : XXX (XX%)
  passed     : XXX (XX%)   ← только прошедшие все фильтры

[Unified] Done: 300 scanned | passed=X | no_bars=X | all_fail=X | low_score=X
```

Если `below_ema > 40%` — рынок в коррекции (порог автоматически 60 → 52),
мало сигналов это норма.
